# Security Policy

## Supported release

Security fixes are assessed against the latest release candidate on `main`.

## Reporting a vulnerability

Do not include secrets, credentials, private research content, or exploit details in a public issue. Use GitHub's private vulnerability-reporting or security-advisory workflow for this repository. If that workflow is unavailable, contact the repository maintainer through the private channel published in the repository settings.

Include a minimal reproduction, affected version, impact, and any suggested mitigation. The report should not contain production tokens, customer data, Prompt content, chain-of-thought, or private source documents.

## Security boundaries

ResearchOS treats Workspace isolation, RBAC, Human Review, Evidence traceability, and secret exclusion as release boundaries. Reports that identify a bypass of those boundaries are security-sensitive.
