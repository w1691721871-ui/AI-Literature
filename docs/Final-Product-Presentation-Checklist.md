# Final Product Presentation Checklist

Use this checklist before an FDE interview, customer solution review, or
enterprise product demonstration.

## Product language

- [ ] Use **AI Employee**, **AI Worker**, **Evidence**, **Review**,
  **Artifact**, and **Delivery** consistently.
- [ ] Do not describe a candidate source as approved Evidence.
- [ ] Do not describe the controlled Computer Worker as unrestricted or fully
  autonomous.
- [ ] Do not expose prompts, chain of thought, credentials, internal IDs, or
  technical traces in the presentation path.

## Workspace readiness

- [ ] Sign in with the intended Workspace identity.
- [ ] Confirm the selected Workspace is the correct one.
- [ ] Confirm Demo Workspace boundaries are visible when using Demo access.
- [ ] Confirm administrator-only controls are unavailable to Demo and
  non-administrator roles.
- [ ] Confirm the Solution Showcase opens from the Workspace header and Home.

## Customer story

- [ ] State the building-materials R&D customer scenario.
- [ ] State the business challenge: fragmented sources, difficult opportunity
  discovery, and knowledge that is hard to reuse.
- [ ] Show the governed path: Mission → AI Worker → Evidence → Review →
  Artifact → Organizational Intelligence.
- [ ] Explain that business value is qualitative unless customer data measures
  it.

## Live workflow

- [ ] Create or open a real Workspace-bound Mission.
- [ ] Show the AI Worker’s user-readable plan and current next action.
- [ ] Show the Evidence boundary and its review state.
- [ ] Show a Review decision point before a material conclusion or delivery.
- [ ] Show a traceable Artifact and its recorded review status.
- [ ] If showing Computer work, explain the approval, verification, and
  bounded recovery boundary.

## Organizational learning

- [ ] Open the Solution Showcase organizational learning section.
- [ ] Verify displayed figures come from the active Workspace only.
- [ ] If there are no records, show the intentional no-data state rather than
  inventing metrics.
- [ ] Explain that approved research work creates reusable Workspace knowledge
  over time.

## Final release checks

- [ ] Run the backend test suite.
- [ ] Check frontend syntax and service-worker syntax.
- [ ] Confirm the deployed application loads current runtime configuration.
- [ ] Confirm identity, Workspace access, Review, and Artifact routes return
  expected authorization results.
- [ ] Confirm the presentation mode opens the Solution Showcase without
  exposing unrelated navigation or technical views.
