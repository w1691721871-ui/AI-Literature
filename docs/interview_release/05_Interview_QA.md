# FDE 面试 Q&A

## 为什么做这个项目？

科研团队的难点不只是阅读论文，而是把资料、研究判断、人工确认和项目交付连接起来。ResearchOS 尝试把这一过程做成 Evidence-driven 工作流，而不是单篇论文总结工具。

## 为什么需要 Agent，而不是普通 RAG 问答？

普通问答通常是一次检索、一次生成。ResearchOS 的 Finite Research Loop 会把目标拆成独立子任务，每个子任务单独检索、验证 Evidence、检查条件差异，并根据中间结果决定继续、重规划或停止。它仍受预算和 Human Review 约束，不是无限自主执行。

## 为什么不用 ChatGPT 就够了？

通用聊天工具适合讨论，但默认不会管理“资料范围、Evidence 来源、冲突提示、审核状态和交付过程”。ResearchOS 的价值是把这些产品对象固定在 Workspace 中，并提供可追溯的研究流程。

## RAG 解决什么问题？

RAG 将回答约束在已上传且完成索引的资料范围内，使结果能返回章节级 Evidence。它不保证科研事实正确，也无法弥补资料缺失；资料不足时系统应返回边界提示而不是自由生成结论。

## 如何保证 AI 可信？

1. 空知识库在进入 LLM 生成前由后端拦截。
2. 每个子任务独立保存 Evidence 引用，避免全局证据混用。
3. Claim Extraction 先在句级提取候选主张。
4. Conflict Detection 识别方向差异和条件差异，但不裁决真伪。
5. Reviewer / Leader 通过 Human Review 显式确认，AI 不自动批准或创建正式 Action。

## 如何设计客户交付？

采用 FDE 流程：需求调研 → 授权资料确认 → Workspace 与知识空间配置 → 受控任务验证 → Evidence / Review 复核 → Research Brief 与 Customer Delivery Report → 客户确认。P5 中的场景、蓝图和报告都是方案模板，不替代真实客户实施。

## 如何衡量价值？

不直接声称“效率提升 80%”。当前 P5 展示真实的资料、知识片段、Workspace、任务和审核状态，并提供可用于评估的 Potential 指标：资料集中管理、人工交接步骤和重复检索复用。真实 ROI 需要在客户试运行中定义基线、周期和验收指标。

## 这个项目离生产系统还差什么？

真实身份认证、权限隔离、多租户、协作通知、版本管理、生产级日志与监控、客户数据治理、外部科研数据源、系统化离线评测和长期运行成本控制仍需进一步建设。
